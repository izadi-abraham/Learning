Pattern: | Difficulty: Medium | Date: 24-07-2026

## The problem in my own words
Inputs: stiring "s" & integer "k"
Operation: Choose any character of "s" and change it to any other upercase English character.
Operation cadence: at most "k" times.
Return: The length of the longest substring you can get containing the same letter you can get after performing the above operation.

## 4th version
After discussing with my frined Gepeto, I understoo I need to throw away all the code and start seeing it from a different angle.
That is a sliding window. I need a window which moves to right always.
Right moves in any iteration.
Left might moves depending on a ceratin condition.
We have list of things to define:

The key questions:
- Q: Given any window [left, right], how can we calculate how many replacements are needed to make every character in that window the same?
- A: Count characters that are not the same as my most frequent character in the this window.
- Suppose this window: "AABBA" - A:3 and B:2 => We can either replace all Bs so we need 2 replacement OR replace As that we need 3 replacement. Optimal is 2 replacement, right?

- Q: Suppose the current window is "AABAB". Can we in a way count the optimal max replacement of this window?
- We have the length of the window which is 5.
- We have the most frequent character's count which is 3.
- The replacement will be 5 - 3 = 2.

- Q: How do I know the most frequent character without iterating the whole string?
- A: We don't need the most frequent of whole string, we only need the most frequent of current window, and since we already iterated/visited all characters
in our current window (via left/right) and saved the characters -> frequency of each character in the map (regarding current window only), at any time we know the answer of this question:
"What is the most frequent character count in the current window?" (If left moves we decrease the left character's)
- So the key formula is "replacements = windowLength - maxFrequency" and if replacements is smaller or equl than k then we still have a window that can become the longest possible
substring with same character (of course after the <= k replacements)
- One subtle thing, look at the commented code, that makes the maxFrequency value to be always right, but it increases the time complexity by m (number of possible distinct characters),
in this problem it's only uppercase English letter and it's about 24 but if the problem is it can be any valid character (m), then it increase the time complexity to be O(m * n).
Since here if keeping an upper bound of max frequency doesn't harm us, so it is a trade off to let be slightly and for a short period of time wrong.


```ts
function characterReplacement(s: string, k: number): number {
    const frequencyMap = new Map()
  let maxFrequency = 0
  let longest = 0
  let right = 0
  let left = 0

  while(right < s.length){
    let char = s[right]
    let count = frequencyMap.get(char) ?? 0
    
    frequencyMap.set(char, ++count)
    
    maxFrequency = Math.max(maxFrequency, count)


    if((right - left + 1) - maxFrequency > k) {
      char = s[left]
      count = frequencyMap.get(char)
      frequencyMap.set(char, --count)
      // maxFrequency = Math.max(...frequencyMap.values())
      left++
    }

    longest = Math.max(longest, right - left + 1)
    right++
  }

  return longest
};

```
